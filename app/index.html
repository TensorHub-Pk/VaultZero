Why VaultZero

Built for People Who Take Privacy Seriously

Every design decision was made with one goal: your data should be mathematically impossible for anyone — including us — to access.

Zero-Knowledge Architecture

All cryptographic operations execute in your browser. No server ever sees your plaintext, keys, or metadata. We can't read your data — by design.

Offline-First

After one initial load, VaultZero works entirely offline. No internet required to encrypt, decrypt, sign, or verify. Your vault is always available.

Post-Quantum Resistance

Hybrid key exchange combines classical X25519 with ML-KEM-768 (Kyber). WOTS+ Merkle signatures provide quantum-safe digital signatures using only hash functions.

File & Text Encryption

Encrypt text messages or entire files. Every payload is wrapped in an integrity-checked envelope with SHA-256 tamper detection and optional auto-expiration.

Secure Share

Generate a cryptographic identity and share encrypted messages with anyone. Only the intended recipient's private key can decrypt the payload.

Steganography

Hide encrypted payloads inside ordinary images using LSB encoding. The existence of your message becomes invisible — not just unreadable.

Honest Security

Threat Model

Transparency about what we protect against — and what we don't — is the foundation of real security.

Protects Against

  • Server-side data breaches — there is no server
  • Man-in-the-middle interception of plaintext
  • Mass surveillance and bulk data collection
  • Future quantum computer attacks on key exchange
  • Timing side-channel attacks on hash comparisons
  • Payload tampering via integrity hash verification
  • Downgrade attacks on app updates
  • Unauthorized update injection (Ed25519 signed manifests)

Does NOT Protect Against

  • Compromised device or OS-level keyloggers
  • Physically coerced disclosure of passwords
  • Malicious browser extensions with DOM access
  • Side-channel attacks on the host hardware
  • Weak or reused passwords chosen by the user
  • Screenshots or screen recording during use

Assumptions

VaultZero assumes the user's device, operating system, and browser are not compromised. It assumes the initial download of the application is authentic. All security guarantees depend on these assumptions being true.

Under the Hood

Security Architecture

The cryptographic primitives and design decisions that make VaultZero trustworthy.

Symmetric Encryption
ChaCha20-Poly1305

AEAD cipher via Libsodium WASM. Hardware-accelerated AES-256-GCM fallback via Web Crypto API.

Key Derivation
Argon2id

Memory-hard KDF with t=3, 64MB memory cost. PBKDF2-SHA256 fallback with 600,000 iterations.

Key Exchange
X25519 + ML-KEM-768

Hybrid classical/post-quantum key exchange. Shared secrets combined via BLAKE2b hash derivation.

Classical Signatures
Ed25519

Detached signatures for identity verification and signed update manifests. Keys zeroed after use.

PQ Signatures
WOTS+ / Merkle

Hash-based quantum-resistant signatures. Winternitz w=16, 67 chains, tree height 4. Pure SHA-256.

Network Policy
Total Isolation

After init, fetch/XHR/WebSocket/EventSource/sendBeacon are all permanently disabled for the session.
